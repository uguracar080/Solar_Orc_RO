# Integrated Solar-ORC-RO System Model Overview

Last updated: 2026-08-17

## Purpose

This repository is being organized as an integrated solar thermal - ORC - RO desalination system model.

The short-term target is not optimization yet. The first target is a single fixed configuration that runs end-to-end and proves that the existing component models exchange physically consistent inputs and outputs.

The long-term target is an annual-analysis function that can evaluate each candidate generated by an optimization algorithm and return water production, energy use, feasibility flags, and objective-function metrics such as levelized cost of water.

## Current V1 Scope

V1 is the first working single-configuration system.

Included in V1:

- Weather and seawater hourly inputs.
- Simplified PTC solar-field model derived from the old solar work.
- ORC fixed-geometry design and off-design/dispatch using `ORC_v23`.
- ORC condenser cooling-water loop.
- New seawater preheater between the ORC condenser outlet water and RO feed seawater.
- Cooling tower as trim/backup heat rejection after the preheater.
- Frozen RO ANN surrogate.
- Manual installed RO train count with hourly active-train dispatch.
- Solar-loop flow modulation around the 56.8 L/min per-module catalog reference.
- Solar circulation-pump power bookkeeping.
- Temporary sensible-water storage bookkeeping for excess solar heat.
- Hourly energy, heat, water, and feasibility/status bookkeeping.

Excluded from V1:

- PCM storage operation and charge/discharge control.
- Optimization algorithm.
- Economic/LCoW model.

PCM files remain in the repository for later integration. The active V1 storage layer is only a water-tank placeholder so excess solar heat can be tracked through a stable interface before PCM is connected.

## V1 System Architecture

The intended V1 hourly chain is:

```text
Weather + seawater profile
  -> solar field
  -> ORC hot-side boundary stream
  -> ORC fixed-geometry off-design dispatch
  -> ORC condenser hot cooling-water outlet
  -> seawater preheater
  -> RO ANN surrogate
  -> cooling tower trim
  -> hourly system balance and status
```

The active V1 coupling is now hourly and closed-loop iterative:

1. The solar loop inlet temperature is guessed from the previous accepted hour or the configuration default.
2. The solar field reads that hour's weather and calculates the hot loop outlet.
3. If solar flow control is enabled, the solver tests configured flow factors around the 56.8 L/min per-module catalog reference and chooses a flow that targets the HTF outlet temperature while respecting the maximum temperature as much as possible.
4. ORC off-design dispatch receives the selected solar outlet as the evaporator hot-side inlet.
5. The solar-loop pump power is calculated from solar-field pressure drop plus ORC evaporator hot-side pressure drop and is subtracted from the ORC net power.
6. The ORC evaporator hot-side outlet becomes the next solar-field inlet guess.
7. The ORC condenser receives the condenser-loop return temperature from the preheater/cooling-tower loop.
8. The condenser outlet water goes to the RO seawater preheater, then to the cooling tower if needed.
9. The cooling-tower outlet becomes the next ORC condenser inlet guess.
10. RO installed train count is dispatched from `N_train_total` down to the largest powered feasible count after solar-pump and cooling-tower auxiliary loads.
11. Any solar useful heat not accepted by the ORC evaporator is sent to the temporary storage interface. With the V1 return-sink option enabled, the storage placeholder can extract heat from the ORC hot-side outlet before the HTF returns to the solar field. If the water-tank placeholder is full or disabled, that heat is reported as curtailed.
12. The hour accepts the final fixed-geometry result and records loop residuals/convergence flags.

The older sequential dispatcher remains in the repository as `system_hourly_dispatch_v1.m`, but the active run path is now `system_hourly_coupled_solver_v1.m`.

Important V1 hot-stream handling:

- The solar field calculates the loop with Syltherm 800 properties.
- `ORC_v23/orc_stream_properties.m` now includes a local `Syltherm800` external-stream property backend for enthalpy, temperature inversion, density, cp, viscosity, and conductivity.
- `cfg.orc.hot_stream_fluid = 'Syltherm800'` is the default, so the ORC evaporator hot side receives the solar field's actual `T_HTF_out_K` and `mdot_HTF_kg_s`.
- `cfg.orc.hot_stream_fluid = 'Water'` remains available for comparison runs; only then does the coupled solver use a water-equivalent solar heat adapter.
- The current Syltherm table is extrapolated if loop temperatures exceed the 400 C table limit. This should be avoided in final studies by enforcing HTF operating limits and/or changing solar-field flow/area/ORC heat extraction.
- The current coupled solver is intentionally direct and robust, not fast. Each hourly coupling iteration may call ORC dispatch again, so annual/optimization runs will need speed improvements after the physics is settled.

Important V1 HTF note:

- `solar_field_ptc_v1.m` calculates a Syltherm-800-like PTC field output.
- `cfg.solar.V_Lmin_1module_reference = 56.8` is the catalog per-module volume flow reference.
- `cfg.solar.flow_control.factor_list` defines the allowed hourly flow modulation percentages relative to that reference.
- The current V1 default solar field is `N_series = 5`, `N_parallel = 20`. This reduces the number of collectors from the earlier 12 x 12 trial while keeping capacity mainly through parallel branches; series count primarily controls temperature rise, while parallel count primarily controls total heat capacity.
- The selected hourly flow is reported as `solar_flow_factor` and `solar_V_Lmin_1module`.
- Solar pump power is reported as `W_solar_pump_W` and is subtracted before RO power dispatch.
- `T_orc_hot_return_raw_C` reports the ORC evaporator hot-side outlet before the temporary storage return sink.
- `T_orc_hot_return_C` reports the actual HTF return temperature sent back to the solar field after the return sink.
- `Q_solar_return_sink_W` reports the heat extracted from the hot return line by the temporary storage interface.
- The ORC evaporator hot side can now use `Syltherm800` through the local external-stream backend in `orc_stream_properties.m`.
- Water remains selectable for comparison or debugging, but it is no longer the default solar-ORC coupling fluid.

The ORC module internally uses SI units; the system wrapper should make all unit conversions explicit.

### Preheater input and output

Preheater purpose:

- Recover heat from the ORC condenser cooling-water loop.
- Heat raw seawater before it enters the RO ANN surrogate.
- Keep condenser-loop water and seawater physically separated.

Preheater type:

- Shell-and-tube heat exchanger.
- Single-phase water/cooling-water side.
- Single-phase seawater side.
- Fixed area after design.
- V1 uses a local preheater copy of the ORC_v23 STHE geometry and single-phase heat-transfer/pressure-drop kernels:
  - `preheater_sthe_core_v1('geometry',...)`
  - `preheater_sthe_core_v1('shell_singlephase',...)`
  - `preheater_sthe_core_v1('tube_singlephase',...)`
- The preheater does not call ORC STHE helper functions at runtime. The equations/correlation structure are copied into the preheater core so the component remains independent and readable.
- V1 preheater convention: ORC condenser-loop water on shell side, seawater on tube side.
- The preheater is sized once at the design point for `raw seawater + preheater.T_RO_in_rise_C`, subject to the minimum approach limit.
- During annual/hourly operation, preheater geometry remains fixed; the rating step only calculates what the frozen geometry can transfer at that hour.

Expected `PHOut` fields:

- `Q_recovered_W`
- `T_RO_in_C`
- `T_sw_out_C`
- `T_cw_out_C`
- `A_ratio`
- `feasible`
- `status`

Recommended runtime method:

- Use effectiveness-NTU for robust hourly rating.
- Keep LMTD and minimum-approach checks for design diagnostics.

### Cooling tower input and output

The cooling tower receives post-preheater condenser-loop water.

Expected input fields:

- `T_w_in_C`
- `mdot_water`
- `T_w_out_target_C`

Expected output fields already available from the CT module:

- `T_w_out_C`
- `Q_rejected_W`
- `W_fan_W`
- `mdot_makeup_kg_s`
- `feasible`
- `status`

### RO ANN input and output

V1 must call:

```matlab
Out = ro_predict_ann_surrogate_v1_9_1(ModelFile, Qf_train_m3h, T_RO_in_C, Cf_kg_m3, R_target);
```

Frozen ANN hard domain:

- `47.5 <= Qf_train_m3h <= 63.0`
- `20.0 <= T_RO_in_C <= 45.0`
- `38.5 <= Cf_kg_m3 <= 41.5`
- `0.399 <= R_target <= 0.571`

Important RO rules:

- Do not retrain the ANN.
- Do not clamp ANN inputs.
- If an input is outside the ANN domain, RO is not considered operating for that hour.
- `W_RO_train_kW` already includes the train-level pump/booster/PX electrical consumption represented by the ANN.
- Do not add the same RO pump powers again.
- `Qp_train_m3h = Qf_train_m3h * R_target` is physics-derived in the ANN wrapper.

V1 scaling:

- `N_train_total` is the installed train count and is specified manually for V1.
- Hourly `N_train_running` is selected by dispatch.
- Dispatch tries `N_train_total` down to 1 and chooses the largest RO train count that is inside the ANN domain, feasible, and powered by ORC net electricity after CT fan power.
- `W_RO_total = N_train_running * W_RO_train_kW`.
- `Qp_total = N_train_running * Qp_train_m3h`.
- If even one train cannot be powered, RO stays off and the hour is flagged as `POWER_DEFICIT`.
